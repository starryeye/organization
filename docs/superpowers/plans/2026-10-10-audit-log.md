# 변경 이력(감사 로그) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 직원·조직마다 "언제, 무엇 때문에(회차 id·SCIM traceId), 조직도와 권한이 어떻게 바뀌었나" 를 30일 남기고, 관리 API 로 최신순으로 읽는다.

**Architecture:**
- **core.**
  - 이력 모델(`core.audit`)을 둔다.
  - `AuditChanges` 는 대상별 변경을 모은다.
  - 기록기 `AuditRecorder` 는 실패를 삼키고 빠진 줄을 센다.
  - 포트는 `AuditLog`·`TraceIds` 둘이다.
  - 전체 교체의 비교 결과는 `DirectoryChanges` 로 돌려준다.
- **흐름.**
  - LDAP 동기화·재적재와 SCIM 재적재는 `SyncJobs.startLockedThen` 의 "반납 뒤 할 일"에서 남긴다.
  - SCIM 쓰기는 `IncrementalSyncUseCase` 가 락을 반납하고 차례를 넘긴 뒤, 응답 전에 남긴다.
- **storage-dynamodb.**
  - `DynamoDbAuditLog`:
    - 파티션 `AUDIT#<종류>#<id>`.
    - 정렬키 `<시각>#<원인 id>#<조각>`.
    - TTL `expiresAt`.
    - 큰 목록은 조각으로 나눈다.
  - `replaceWith` 가 실제로 쓴 것을 돌려준다.
- **admin-api.** 이력 조회 두 경로를 둔다.

**Tech Stack:**
- Java 17, Spring Boot 3.5 WebFlux, Reactor.
- AWS SDK v2 DynamoDB: BatchWriteItem, 역순 Query, TTL, DeleteItem `ALL_OLD`.
- Micrometer Tracing(OTel 브리지)·context-propagation.
- Jackson.
- 테스트: JUnit 5, AssertJ, WebTestClient, Testcontainers(DynamoDB Local, OpenFGA), UnboundID 임베디드 LDAP.

**Spec:** `docs/superpowers/specs/2026-10-10-audit-log-design.md`

- **테스트 표지.** 모든 테스트에 `// given`·`// when`·`// then` 표지를 둔다.

  - 계획의 코드에 표지가 빠져 있으면 더한다.

  - 클래스 이름은 영어다.
  - 메서드 이름은 그 파일의 관례를 따른다. 공개 API·포트·DTO 는 영어이고, 저장소 안 도우미와 테스트는 한국어다.
- **커밋.**
  - 제목은 한국어로 쓴다.
  - 빈 줄 다음에 자기 하네스가 주는 `Co-Authored-By:` 줄을 단다(heredoc).
  - 커밋마다 `git push` 한다.

  - 한 번에 하나씩 포그라운드로 돌린다.
  - 과제가 정한 모듈 테스트만 돌린다. `scaleTest`·전체 `test` 는 컨트롤러 몫이다.

- **키(spec §3.2·§3.4).**
  - 파티션키: `Keys.auditPk(subject)`.
    - `AUDIT#USER#<직원 id>` 또는 `AUDIT#GROUP#<조직 id>` 이다.
  - 정렬키: `Keys.auditSk(at, causeId, part)`.
    - `<Keys.sortableTimestamp(at)>#<원인 id>#<조각 번호 네 자리>` 이다.
    - 조각이 하나여도 `#0000` 을 붙인다.
- **아이템 속성 이름.**
  - 원인과 시각: `at`(`Instant.toString()`), `source`, `kind`, `causeId`.
  - 조각: `part`, `parts`.
  - 첫 조각에만 싣는 것: `created`, `deleted`(BOOL, 참일 때만), `attributes`(L of M, 키는 `name`·`before`·`after`, null 인 키는 넣지 않음).
  - 목록(L of S, 비면 넣지 않음): `joined`, `left`, `membersAdded`, `membersRemoved`, `granted`, `revoked`.
  - 보관: `expiresAt`(`Keys.EXPIRES_AT`).
- **값 형식.**
  - 멤버: `USER#kim`, `GROUP#DEV`.
  - 저장하는 튜플: `user:kim|direct_member|group:DEV`.
  - API 의 튜플: `user:kim direct_member group:DEV`.
- **원인(spec §3.3).**
  - `source`: `LDAP`·`SCIM`(`SyncSource`).
  - `kind`: `SYNC`·`REBUILD`·`LEDGER_ALIGNMENT`·`SCIM_REQUEST`(`AuditKind`).
  - `id`: 회차의 `runId`, 또는 SCIM 요청의 traceId. traceId 를 모르면 임의 UUID 를 쓴다.
- **속성 이름(spec §3.3).**
  - 직원(이 순서): `externalId`, `userName`, `displayName`, `email`, `active`, `name.formatted`, `name.familyName`, `name.givenName`, `name.middleName`, `name.honorificPrefix`, `name.honorificSuffix`.
  - 조직: `externalId`, `displayName`.
  - 빈 문자열은 없는 값(null)으로 본다.
- **보관(spec §6).**
  - 설정은 `dynamodb.audit-retention-days` 이고 기본 30이다.
  - `expiresAt` 은 기록 시각 + 일수(epoch 초)다.
- **쓰는 시점과 실패(spec §4.4·§4.5).**
  - 커밋한 뒤에 쓴다. 락을 반납한 뒤에 쓴다.
  - 이력 쓰기가 실패해도 작업은 실패하지 않는다. 대신 셋으로 알린다.
    - ERROR 로그.
    - 지표 `audit.write.failures`(빠진 줄 수만큼 오른다).
    - 회차 메시지 앞에 `감사 기록 N건 실패` 를 붙인다(`SyncOutcome.withNote`).
- **남기지 않는 것(spec §3.5).**
  - 재적재·장부 맞추기가 쓴 튜플은 남기지 않는다. 지운 튜플은 남긴다.
  - 아카이빙은 남길 것이 없다.
- **조회 API(spec §5).**
  - 경로: `GET /admin/employees/{employeeId}/history`, `GET /admin/organizations/{orgCode}/history`.
  - `limit` 은 기본 20이고 1..100 이다. 밖이면 400 이다.
  - 위조·손상 커서는 400 이다.
  - 기록이 없는 아이디는 200 과 빈 목록이다.
  - 다음 쪽 커서는 이번 쪽이 `limit` 줄로 찼을 때 준다. 그래서 마지막 쪽 뒤에 빈 쪽이 하나 올 수 있다(DynamoDB `LastEvaluatedKey` 와 같은 성질).
- **조각 한도.** `DynamoDbAuditLog.PART_BUDGET = 300_000` 이다. 목록 값 하나를 UTF-8 바이트 + 4 로 센다.
- **그대로인 것.**
  - 도메인 레코드 `DirectoryUser`·`GroupHeader`·`DirectoryGroup` 은 바꾸지 않는다.
  - 기존 공개 생성자는 남긴다. 옛 생성자는 이력 없이(`AuditRecorder.NONE`, `TraceIds.NONE`) 돈다.
  - 운영 결선만 새 생성자를 쓴다.

```java
        Objects.requireNonNull(kind, "kind");
        Objects.requireNonNull(id, "id");

    public static AuditCause scimRequest(String traceId) {
```

```java
        List<AttributeChange> attributes,

        List<MemberRef> membersAdded,
        List<MemberRef> membersRemoved,
        List<RelationTuple> granted,
        List<RelationTuple> revoked
) {
```

```java
package dev.starryeye.organization.core.model;

import java.util.List;
import java.util.Set;

/**
 * 전체 교체({@code DirectoryStateRepository.replaceWith})가 실제로 쓴 것 — 저장본과 비교해 바뀐 직원·조직만 담는다(설계 2026-10-10 §4.3). 같은 조직도면
 * 비어 있다. 이력이 이것으로 조직도 변경을 남긴다.
 *
 * @param users  직원마다 이전·이후. 이전이 null 이면 생성, 이후가 null 이면 삭제다
 * @param groups 조직마다 이름표의 이전·이후와 들어오고 나간 멤버. 이전이 null 이면 생성, 이후가 null 이면 삭제다
 */
public record DirectoryChanges(List<UserDiff> users, List<GroupDiff> groups) {

    public DirectoryChanges {
        users = users == null ? List.of() : List.copyOf(users);
        groups = groups == null ? List.of() : List.copyOf(groups);
    }

    public static DirectoryChanges none() {
        return new DirectoryChanges(List.of(), List.of());
    }

    public boolean isEmpty() {
        return users.isEmpty() && groups.isEmpty();
    }

    public record UserDiff(DirectoryUser before, DirectoryUser after) {

        public UserDiff {
            if (before == null && after == null) {
                throw new IllegalArgumentException("이전과 이후가 모두 비었다");
            }
        }

        public String id() {
            return after != null ? after.id() : before.id();
        }
    }

    /** 이름표가 그대로이고 멤버만 바뀌었으면 이전과 이후가 같은 이름표다. */
    public record GroupDiff(GroupHeader before, GroupHeader after, Set<MemberRef> added, Set<MemberRef> removed) {

        public GroupDiff {
            if (before == null && after == null) {
                throw new IllegalArgumentException("이전과 이후가 모두 비었다");
            }
            added = added == null ? Set.of() : Set.copyOf(added);
            removed = removed == null ? Set.of() : Set.copyOf(removed);
        }

        public String id() {
```

```java
    /** 아무것도 남기지 않는다 — 이력과 무관한 테스트와 옛 생성자가 쓴다. */
    public static final AuditRecorder NONE = new AuditRecorder(AuditLog.NONE, AuditObserver.NOOP, Clock.systemUTC());

    static final String 실패_메모 = "감사 기록 %d건 실패";

    private final AuditLog auditLog;
    private final AuditObserver observer;
    private final Clock clock;

    public AuditRecorder(AuditLog auditLog, AuditObserver observer, Clock clock) {
        this.auditLog = auditLog;
        this.observer = observer;
        this.clock = clock;
    }

    /**
     * 사건 하나를 남긴다. 남길 것이 없는 줄은 빼고, 하나도 없으면 쓰지 않는다 — 같은 조직도를 다시 동기화하면 쓰기가 0번이다(§3.6). 시각은 지금(서버
     * 시계)이다.
     *
     * @return 쓰지 못한 줄 수. 0 이면 다 썼다. 저장소가 오류로 끝나면 남기려던 줄 전부다
     */
    public Mono<Integer> record(AuditCause cause, List<AuditEntry> entries) {
        return Mono.defer(() -> {
            List<AuditEntry> 남길것 = entries.stream().filter(entry -> !entry.isEmpty()).toList();
            if (남길것.isEmpty()) {
                return Mono.just(0);
            }
            AuditEvent event = new AuditEvent(clock.instant(), cause, 남길것);
            return Mono.defer(() -> auditLog.write(event))

                        if (빠진 > 0) {
                            observer.writeFailed(빠진);
                        }
                    });
        });
```

```java
    /** 변경 이력 파티션키 — 대상 종류와 id(설계 2026-10-10 §3.2). 직원·조직의 본 파티션과 따로라 직원·조직을 지워도 남는다. */
    public static String auditPk(MemberRef subject) {
        return AUDIT_PREFIX + subject.type().name() + "#" + subject.id();
    }

    /**
     * 변경 이력 정렬키 — {@code <시각>#<원인 id>#<조각 번호>}(설계 2026-10-10 §3.2·§3.4). 조각이 하나여도 {@code #0000} 을 붙인다. 역순 Query 가 곧
     * 최신순이고, 한 줄의 조각은 번호가 큰 것부터 나와 0번이 마지막이다.
     */
    public static String auditSk(Instant at, String causeId, int part) {
        if (part < 0 || part > 9_999) {
            throw new IllegalArgumentException("조각 번호는 0~9999 다: " + part);
        }
        return sortableTimestamp(at) + "#" + causeId + "#" + "%04d".formatted(part);
    }

    /** 조각 번호를 뗀 정렬키 — 한 줄의 조각끼리 같다. 원인 id 에는 {@code #} 이 없다(runId 는 UUID, traceId 는 16진수). */
    public static String auditRecordKey(String sk) {
        return sk.substring(0, sk.lastIndexOf('#'));
    }
```

```java
/**
 * 변경 이력(설계 2026-10-10 §3·§5). 대상 하나 × 사건 하나가 한 줄이다.
 *
 * <ul>
 *   <li>파티션은 {@code AUDIT#USER#<id>}·{@code AUDIT#GROUP#<id>}, 정렬키는 {@code <시각>#<원인 id>#<조각>} 이다({@link Keys#auditPk}·{@link Keys#auditSk}).</li>

 *   <li>줄마다 {@code expiresAt}(기록 시각 + {@code dynamodb.audit-retention-days})을 넣어 테이블 TTL 이 지운다.</li>
 * </ul>
 *
 * <p><b>조각(§3.4).</b> 목록(소속·멤버·튜플)이 아이템 한도(400KB)를 넘으면 한 줄을 조각 몇 개로 나눈다. 앞 조각부터 목록 순서대로 채우고, 조각마다
 * 전체 조각 수를 적는다. 머리(생성·삭제·속성)는 0번 조각에만 싣는다. 읽을 때 조각을 합치고, 조각이 모자란 줄(쓰다 일부만 남음)은 버린다 — 빠질 수는
 * 있어도 틀린 줄은 돌려주지 않는다.
 *
 * <p><b>쓰기(§4.1).</b> 묶음 쓰기({@link BatchRequests} — 25개씩, 처리 못 한 것은 5번까지 다시 보낸다)다. 묶음 하나가 끝내 실패해도 나머지는 계속
 * 쓰고, 실패한 아이템 수를 돌려준다.
 */
@Slf4j
public class DynamoDbAuditLog implements AuditLog {

    /** 조각 하나에 담을 목록 값의 어림 바이트(값의 UTF-8 바이트 + 4). 아이템 한도 400KB 에서 속성 이름·머리 몫을 남긴다. */
    static final int PART_BUDGET = 300_000;

    private static final int WRITE_CONCURRENCY = 8;
    /** DynamoDB 정렬키 한도. 위조 커서의 시작 키가 넘으면 ValidationException(500)이 된다. */
    private static final int MAX_SORT_KEY_BYTES = 1024;
    private static final String SCOPE_PREFIX = "AUDIT/";

    private static final String AT = "at";
    private static final String SOURCE = "source";
    private static final String KIND = "kind";
    private static final String CAUSE_ID = "causeId";
    private static final String PART = "part";
    private static final String PARTS = "parts";
    private static final String CREATED = "created";
    private static final String DELETED = "deleted";
    private static final String ATTRIBUTES = "attributes";
    private static final String NAME = "name";
    private static final String BEFORE = "before";
    private static final String AFTER = "after";
    private static final String JOINED = "joined";
    private static final String LEFT = "left";
    private static final String MEMBERS_ADDED = "membersAdded";
    private static final String MEMBERS_REMOVED = "membersRemoved";
    private static final String GRANTED = "granted";
    private static final String REVOKED = "revoked";
    private static final String TUPLE_SEPARATOR = "|";

    private final DynamoDbAsyncClient client;
    private final DynamoDbProperties properties;
    private final BatchRequests batches;
    private final int partBudget;

    public DynamoDbAuditLog(DynamoDbAsyncClient client, DynamoDbProperties properties) {
        this(client, properties, PART_BUDGET);
    }

    /** 조각 한도를 정한다 — 테스트가 작은 한도로 나누기·합치기를 본다. */
    DynamoDbAuditLog(DynamoDbAsyncClient client, DynamoDbProperties properties, int partBudget) {
        this.client = client;
        this.properties = properties;
        this.batches = new BatchRequests(client, properties.getTableName());
        this.partBudget = partBudget;
    }

    @Override
    public Mono<Integer> write(AuditEvent event) {
        long expiresAt = event.at().plus(Duration.ofDays(properties.getAuditRetentionDays())).getEpochSecond();
        return Flux.fromIterable(event.entries())
                .concatMapIterable(entry -> 아이템들(event, entry, expiresAt))
                .map(item -> WriteRequest.builder().putRequest(PutRequest.builder().item(item).build()).build())
                .buffer(BatchRequests.WRITE_LIMIT)
                .flatMap(batch -> batches.write(batch)
                        .thenReturn(0)
                        .onErrorResume(error -> {
                            log.error("감사 기록 묶음 하나({}줄)를 쓰지 못했다 — 원인 {}", batch.size(), event.cause().id(), error);
                            return Mono.just(batch.size());
                        }), WRITE_CONCURRENCY)
                .reduce(0, Integer::sum);
    }

    /** 한 줄을 조각 아이템으로 — 목록 값을 앞 조각부터 채운다. 머리(생성·삭제·속성)는 0번 조각에만 싣는다. */
    private List<Map<String, AttributeValue>> 아이템들(AuditEvent event, AuditEntry entry, long expiresAt) {
        Map<String, List<String>> 목록 = new LinkedHashMap<>();
        목록.put(JOINED, entry.joined());
        목록.put(LEFT, entry.left());
        목록.put(MEMBERS_ADDED, entry.membersAdded().stream().map(DynamoDbAuditLog::멤버값).toList());
        목록.put(MEMBERS_REMOVED, entry.membersRemoved().stream().map(DynamoDbAuditLog::멤버값).toList());
        목록.put(GRANTED, entry.granted().stream().map(DynamoDbAuditLog::튜플값).toList());
        목록.put(REVOKED, entry.revoked().stream().map(DynamoDbAuditLog::튜플값).toList());

        List<Map<String, List<String>>> 조각들 = new ArrayList<>();
        Map<String, List<String>> 지금 = new LinkedHashMap<>();
        조각들.add(지금);
        int 크기 = 0;
        for (Map.Entry<String, List<String>> 한_목록 : 목록.entrySet()) {
            for (String value : 한_목록.getValue()) {
                int size = value.getBytes(StandardCharsets.UTF_8).length + 4;
                if (크기 > 0 && 크기 + size > partBudget) {
                    지금 = new LinkedHashMap<>();
                    조각들.add(지금);
                    크기 = 0;
                }
                지금.computeIfAbsent(한_목록.getKey(), ignored -> new ArrayList<>()).add(value);
                크기 += size;
            }
        }

        List<Map<String, AttributeValue>> items = new ArrayList<>();
        for (int part = 0; part < 조각들.size(); part++) {
            Map<String, AttributeValue> item = new HashMap<>();
            item.put(Keys.PK, Attrs.s(Keys.auditPk(entry.subject())));
            item.put(Keys.SK, Attrs.s(Keys.auditSk(event.at(), event.cause().id(), part)));
            item.put(AT, Attrs.s(event.at().toString()));
            item.put(SOURCE, Attrs.s(event.cause().source().name()));
            item.put(KIND, Attrs.s(event.cause().kind().name()));
            item.put(CAUSE_ID, Attrs.s(event.cause().id()));
            item.put(PART, Attrs.n(part));
            item.put(PARTS, Attrs.n(조각들.size()));
            item.put(Keys.EXPIRES_AT, Attrs.n(expiresAt));
            if (part == 0) {
                if (entry.created()) {
                    item.put(CREATED, Attrs.bool(true));
                }
                if (entry.deleted()) {
                    item.put(DELETED, Attrs.bool(true));
                }
                if (!entry.attributes().isEmpty()) {
                    item.put(ATTRIBUTES, 속성값(entry.attributes()));
                }
            }
            조각들.get(part).forEach((name, values) -> item.put(name, 문자열_목록(values)));
            items.add(item);
        }
        return items;
    }

    @Override
    public Mono<Page<AuditRecord>> history(MemberRef subject, String cursor, int limit) {
        String pk = Keys.auditPk(subject);
        String scope = SCOPE_PREFIX + pk;
        return Mono.defer(() -> {
            QueryRequest.Builder request = QueryRequest.builder()
                    .tableName(properties.getTableName())
                    .keyConditionExpression("#pk = :pk")
                    .expressionAttributeNames(Map.of("#pk", Keys.PK))
                    .expressionAttributeValues(Map.of(":pk", Attrs.s(pk)))
                    .scanIndexForward(false);
            Map<String, AttributeValue> start = Cursor.decode(scope, cursor);
            if (start != null) {
                request.exclusiveStartKey(시작_키를_확인한다(start, pk));
            }
            return Paginator.queryAll(client, request.build())
                    // 역순이라 한 줄의 조각은 번호가 큰 것부터 오고 0번이 마지막이다 — 0번에서 끊으면 쪽 경계가 조각 사이에 걸리지 않는다(§5)
                    .bufferUntil(item -> Attrs.integer(item, PART) == 0)
                    .concatMapIterable(조각들 -> 합친다(subject, 조각들).stream().toList())
                    .take(limit)
                    .collectList()
                    .map(줄들 -> new Page<>(
                            줄들.stream().map(읽은줄::record).toList(),
                            줄들.size() == limit ? Cursor.encode(scope, 줄들.get(줄들.size() - 1).key()) : null));
        });
    }

    /** 읽은 줄과, 다음 쪽이 이어 읽을 그 줄의 0번 조각 키. */
    private record 읽은줄(AuditRecord record, Map<String, AttributeValue> key) {
    }

    /**
     * 한 줄의 조각(역순)을 합친다. 0번 조각과 같은 줄의 조각만 쓰고, 그 수가 0번 조각이 적은 전체 조각 수와 같을 때만 돌려준다 — 앞 줄의 남은 조각이
     * 섞여 있으면(첫 조각을 잃은 줄) 그것은 버린다.
     */
    private Optional<읽은줄> 합친다(MemberRef subject, List<Map<String, AttributeValue>> 조각들) {
        Map<String, AttributeValue> 첫조각 = 조각들.get(조각들.size() - 1);
        String 줄 = Keys.auditRecordKey(Attrs.str(첫조각, Keys.SK));
        List<Map<String, AttributeValue>> 이줄 = new ArrayList<>(조각들.stream()
                .filter(item -> 줄.equals(Keys.auditRecordKey(Attrs.str(item, Keys.SK))))
                .toList());
        if (이줄.size() < 조각들.size()) {
            log.warn("첫 조각을 잃은 감사 기록의 남은 조각 {}개를 건너뛴다: {}", 조각들.size() - 이줄.size(), Attrs.str(첫조각, Keys.PK));
        }
        if (Attrs.integer(첫조각, PART) != 0 || Attrs.integer(첫조각, PARTS) != 이줄.size()) {
            log.warn("조각이 모자란 감사 기록을 건너뛴다: {} {}", Attrs.str(첫조각, Keys.PK), 줄);
            return Optional.empty();
        }
        Collections.reverse(이줄);

        AuditCause cause = new AuditCause(SyncSource.valueOf(Attrs.str(첫조각, SOURCE)),
                AuditKind.valueOf(Attrs.str(첫조각, KIND)), Attrs.str(첫조각, CAUSE_ID));
        AuditEntry entry = new AuditEntry(subject,
                Attrs.flag(첫조각, CREATED),
                Attrs.flag(첫조각, DELETED),
                속성들(첫조각),
                이어붙인다(이줄, JOINED),
                이어붙인다(이줄, LEFT),
                이어붙인다(이줄, MEMBERS_ADDED).stream().map(DynamoDbAuditLog::멤버).toList(),
                이어붙인다(이줄, MEMBERS_REMOVED).stream().map(DynamoDbAuditLog::멤버).toList(),
                이어붙인다(이줄, GRANTED).stream().map(DynamoDbAuditLog::튜플).toList(),
                이어붙인다(이줄, REVOKED).stream().map(DynamoDbAuditLog::튜플).toList());
        AuditRecord record = new AuditRecord(Instant.parse(Attrs.str(첫조각, AT)), cause, entry);
        return Optional.of(new 읽은줄(record, Map.of(Keys.PK, 첫조각.get(Keys.PK), Keys.SK, 첫조각.get(Keys.SK))));
    }

    /**
     * 커서에서 꺼낸 시작 키를 그대로 믿지 않는다(점검 S16 앞쪽과 같은 검사). 범위만 맞춘 위조 커서가 다른 파티션을 가리키거나 정렬키 한도를 넘으면
     * DynamoDB 가 {@code ValidationException} 을 내 500 이 된다. 이 대상의 이력 키가 아니면 400 으로 갈 예외다.
     *
     * <p>키 집합 검사가 먼저다 — 뒤의 {@code start.get(...)} 은 키가 있다는 것에 기댄다. 값이 문자열인 것은 {@link Cursor#decode} 가 지켰다.
     */
    private static Map<String, AttributeValue> 시작_키를_확인한다(Map<String, AttributeValue> start, String pk) {
        if (!start.keySet().equals(Set.of(Keys.PK, Keys.SK))
                || !pk.equals(start.get(Keys.PK).s())
                || start.get(Keys.SK).s().getBytes(StandardCharsets.UTF_8).length > MAX_SORT_KEY_BYTES) {
            throw new IllegalArgumentException("이 대상의 이력 커서가 아니다");
        }
        return start;
    }

    private static List<String> 이어붙인다(List<Map<String, AttributeValue>> 조각들, String name) {
        List<String> values = new ArrayList<>();
        for (Map<String, AttributeValue> item : 조각들) {
            AttributeValue list = item.get(name);
            if (list != null && list.hasL()) {
                list.l().forEach(value -> values.add(value.s()));
            }
        }
        return values;
    }

    private static AttributeValue 속성값(List<AttributeChange> changes) {
        return AttributeValue.builder().l(changes.stream().map(change -> {
            Map<String, AttributeValue> map = new HashMap<>();
            map.put(NAME, Attrs.s(change.name()));
            Attrs.putIfPresent(map, BEFORE, change.before());
            Attrs.putIfPresent(map, AFTER, change.after());
            return AttributeValue.builder().m(map).build();
        }).toList()).build();
    }

    private static List<AttributeChange> 속성들(Map<String, AttributeValue> item) {
        AttributeValue list = item.get(ATTRIBUTES);
        if (list == null || !list.hasL()) {
            return List.of();
        }
        return list.l().stream()
                .map(value -> new AttributeChange(Attrs.str(value.m(), NAME), Attrs.str(value.m(), BEFORE),
                        Attrs.str(value.m(), AFTER)))
                .toList();
    }

    private static AttributeValue 문자열_목록(List<String> values) {
        return AttributeValue.builder().l(values.stream().map(Attrs::s).toList()).build();
    }

    private static String 멤버값(MemberRef ref) {
        return ref.type().name() + "#" + ref.id();
    }

    private static MemberRef 멤버(String value) {
        String[] parts = value.split("#", 2);
        return new MemberRef(MemberType.valueOf(parts[0]), parts[1]);
    }

    private static String 튜플값(RelationTuple tuple) {
        return tuple.user() + TUPLE_SEPARATOR + tuple.relation() + TUPLE_SEPARATOR + tuple.object();
    }

    private static RelationTuple 튜플(String value) {
        String[] parts = value.split("\\" + TUPLE_SEPARATOR, 3);
        return new RelationTuple(parts[0], parts[1], parts[2]);
    }
}
```

```java
 * {@link SyncJobs#startLockedThen} 의 "반납 뒤 할 일" 이다. 장부를 훑어 맞춘 회차는 지운 줄만 남긴다.

@Slf4j
public class FullSyncUseCase {

    static final String 기준선_의심 = "기준선 의심(지난 회차가 기록 전에 멈춤) — 장부를 훑어 맞춤";

    private final DirectorySnapshotSource source;
    private final TupleSnapshotRepository snapshots;
    private final DirectoryStateRepository state;
    private final RelationTupleWriter writer;
    private final DeletionGuard guard;
    private final SyncJobs jobs;
    private final Clock clock;
    private final AuditRecorder audit;
    private final LedgerAlignment alignment;

    /** 이력을 남기지 않는다 — 이력과 무관한 테스트가 쓴다. 운영 결선은 이력을 받는 생성자다. */
    public FullSyncUseCase(DirectorySnapshotSource source, TupleSnapshotRepository snapshots,
                           DirectoryStateRepository state, RelationTupleWriter writer, RelationTupleScanner scanner,
                           DeletionGuard guard, SyncJobs jobs, Clock clock) {
        this(source, snapshots, state, writer, scanner, guard, jobs, clock, AuditRecorder.NONE);

    public FullSyncUseCase(DirectorySnapshotSource source, TupleSnapshotRepository snapshots,
                           DirectoryStateRepository state, RelationTupleWriter writer, RelationTupleScanner scanner,
                           DeletionGuard guard, SyncJobs jobs, Clock clock, AuditRecorder audit) {
        this.source = source;
        this.snapshots = snapshots;
        this.state = state;
        this.writer = writer;
        this.guard = guard;
        this.jobs = jobs;
        this.clock = clock;
        this.audit = audit;
        this.alignment = new LedgerAlignment(snapshots, state, writer, scanner, guard, clock, audit);
    }

    /**
     * 작업 락(SYNC)을 잡고 실행 기록(RUNNING)을 연 뒤 동기화를 요청과 떼어 띄운다(설계 2026-09-30 §3). 못 잡으면
     * {@link LockUnavailableException} — 다른 인스턴스가 동기화·재적재 중이다. {@code onFinished} 는 끝난 기록으로 불린다(지표·로그).
     */
    public Mono<SyncRun> start(SyncTrigger trigger, Consumer<SyncRun> onFinished) {
        return jobs.startLockedThen(SyncSource.LDAP, trigger, MutationLock.LockPurpose.SYNC,
                run -> Mono.defer(() -> synchronize(trigger, run.runId())), onFinished);
    }

    /** 락 안에서 맞추고 "반납 뒤 할 일"(이력)을 내놓는다. */
    private Mono<Mono<SyncOutcome>> synchronize(SyncTrigger trigger, String runId) {
        return source.fetchAll().flatMap(directory -> {
            TupleMappingResult mapping = TupleMapper.toTuples(directory);
            mapping.warnings().forEach(warning -> log.warn("튜플 변환 경고: {}", warning));

            return snapshots.isWriting().flatMap(writing -> writing
                    ? 훑어_맞춘다(directory, mapping.tuples(), trigger, runId)
                    : 비교해_맞춘다(directory, mapping.tuples(), trigger, runId));
        });
    }

    /**
     * 기준선을 믿을 수 없는 회차 — 재적재와 같은 청소로 한 번 맞춘다. {@code FORCED} 면 삭제 가드를 건너뛴다.
     *
     * <p>청소 자체가 오류로 끝나도(쓰기 단계 차단기, 스냅샷 저장 실패, "기록 중" 표시를 남기지 못함) 기록 메시지에 "기준선 의심" 사정을
     * 남긴다 — 그러지 않으면 FAILED 사유만 보고는 지난 회차가 기록 전에 멈췄다는 맥락이 사라진다. 취소는 {@code onErrorMap} 이
     * 보지 못하므로 여기서 감싸지 않는다.
     */
    private Mono<Mono<SyncOutcome>> 훑어_맞춘다(DirectorySnapshot directory, Set<RelationTuple> desired,
                                               SyncTrigger trigger, String runId) {
        log.warn(기준선_의심);
        return alignment.align(directory, desired, trigger == SyncTrigger.FORCED,
                        AuditCause.run(SyncSource.LDAP, AuditKind.LEDGER_ALIGNMENT, runId))
                .map(반납_뒤 -> 반납_뒤.map(outcome -> outcome.withNote(기준선_의심)))
                .onErrorMap(error -> new IllegalStateException(
                        기준선_의심 + " / " + (error.getMessage() != null ? error.getMessage() : error.getClass().getSimpleName()),
                        error));
    }

    private Mono<Mono<SyncOutcome>> 비교해_맞춘다(DirectorySnapshot directory, Set<RelationTuple> desired,
                                                SyncTrigger trigger, String runId) {
        AuditCause cause = AuditCause.run(SyncSource.LDAP, AuditKind.SYNC, runId);
        return baseline().flatMap(baseline -> {
            TupleDelta delta = TupleDiff.between(baseline, desired);
            if (delta.isEmpty()) {
                log.info("변경 없음. OpenFGA 를 호출하지 않는다");
                return state.replaceWith(directory)
                        .map(changes -> 남긴다(cause, changes, TupleWriteResult.empty(), SyncOutcome.noChange()));
            }
            if (trigger != SyncTrigger.FORCED) {
                GuardDecision decision = guard.evaluate(delta, baseline);
                if (decision.aborted()) {
                    log.warn("삭제 가드 발동: {}", decision.message());
                    return Mono.just(Mono.just(SyncOutcome.aborted(decision.message())));
                }
            }
            // 표시가 쓰기보다 먼저다 — 표시를 남기지 못하면 쓰지 않는다(설계 2026-09-30 §11)
            return snapshots.markWriting()
                    .then(Mono.defer(() -> writer.apply(delta)))
                    .flatMap(result -> commit(directory, baseline, result, cause))
                    .onErrorResume(TupleWriteAbortedException.class, stopped ->
                            saveSnapshotAndState(directory, baseline, stopped.partial())
                                    .map(saved -> 남긴다(cause, saved.changes(), stopped.partial(),
                                            SyncOutcome.stopped(stopped.partial(), saved.snapshotId(), stopped.getMessage()))));
        });
    }

    private Mono<Set<RelationTuple>> baseline() {
        return snapshots.findLatest()
                .map(TupleSnapshot::tuples)
                .defaultIfEmpty(Set.of());
    }

    private Mono<Mono<SyncOutcome>> commit(DirectorySnapshot directory, Set<RelationTuple> baseline,
                                           TupleWriteResult result, AuditCause cause) {
        return saveSnapshotAndState(directory, baseline, result)
                .map(saved -> 남긴다(cause, saved.changes(), result, result.hasFailure()
                        ? SyncOutcome.partial(result, saved.snapshotId())
                        : SyncOutcome.succeeded(result, saved.snapshotId())));
    }

    /**
     * 반납 뒤 할 일 — 회차가 커밋한 조직도 변경과 쓰고 지운 튜플을 회차 id 로 남긴다(설계 2026-10-10 §4.4). 줄은 락을 반납한 뒤에 만든다. 이력을 쓰지
     * 못해도 회차는 그대로이고, 메시지 앞에 빠진 줄이 붙는다(§4.5).
     */
    private Mono<SyncOutcome> 남긴다(AuditCause cause, DirectoryChanges changes, TupleWriteResult result, SyncOutcome outcome) {
        return Mono.defer(() -> audit.recordRun(cause,
                new AuditChanges().directory(changes).tuples(result).entries(), outcome));
    }

    /** 저장한 스냅샷 아이디와, 현재상태가 실제로 바뀐 것. */
    private record 저장함(String snapshotId, DirectoryChanges changes) {
    }

    /**
     * 튜플 스냅샷과 현재상태는 <b>기준이 다르다</b>.
     * 스냅샷은 OpenFGA 에 실제 반영된 것, 현재상태는 LDAP 에서 읽은 사실 그대로다.
     *
     * <p>쓰기가 차단기로 멈췄을 때도 여기를 탄다(설계 2026-09-29 §5) — 이미 나간 쓰기를 스냅샷에 담지 않으면 기준선이 장부와 어긋난다.
     * 스냅샷 저장이 "기록 중" 표시를 지운다. 저장한 스냅샷 아이디와 현재상태가 바뀐 것을 준다.
     */
    private Mono<저장함> saveSnapshotAndState(DirectorySnapshot directory,
                                            Set<RelationTuple> baseline,
                                            TupleWriteResult result) {
        Set<RelationTuple> committed = new HashSet<>(baseline);
        committed.removeAll(result.deleted());
        committed.addAll(result.written());

        Instant now = clock.instant();
        TupleSnapshot snapshot = new TupleSnapshot(
                SnapshotIds.generate(now, SyncSource.LDAP),
                now,
                SyncSource.LDAP,
                committed);

        return snapshots.save(snapshot)
                .then(Mono.defer(() -> state.replaceWith(directory)))
                .map(changes -> new 저장함(snapshot.id(), changes));
    }
}
```

```java
/**

 *   <li>장부를 D 에 맞추되, 지우기 전에 삭제 가드를 본다({@code force} 면 건너뛴다). 가드에 걸리면 지우지 않고 ABORTED — 스냅샷을 남기지 않으므로
 *       표시가 남아 다음 회차도 다시 확인한다.</li>
 *   <li>끝나면 스냅샷(표시가 사라진다)과 현재상태를 남긴다.</li>
 *   <li>락을 반납한 뒤 이력을 남긴다 — 현재상태가 바뀐 것과 <b>지운 줄만</b>. 쓴 줄은 중복 무시로 써 이미 있던 줄과 가를 수 없다(설계 2026-10-10
 *       §3.5).</li>
 * </ol>
 */
@RequiredArgsConstructor
final class LedgerAlignment {

    private final TupleSnapshotRepository snapshots;
    private final DirectoryStateRepository state;
    private final RelationTupleWriter writer;
    private final RelationTupleScanner scanner;
    private final DeletionGuard guard;
    private final Clock clock;
    private final AuditRecorder audit;

    /** 락 안에서 맞추고 "반납 뒤 할 일"(이력)을 내놓는다. 가드에 걸리면 커밋한 것이 없어 남길 것도 없다. */
    Mono<Mono<SyncOutcome>> align(DirectorySnapshot directory, Set<RelationTuple> desired, boolean force,
                                  AuditCause cause) {
        TupleReconciler.DeleteCheck check = force ? TupleReconciler.DeleteCheck.NONE : this::가드로_본다;
        return snapshots.markWriting()
                .then(TupleReconciler.reconcile(writer, scanner, desired, check))
                .flatMap(reconciliation -> reconciliation.held()
                        ? Mono.just(Mono.just(SyncOutcome.aborted(reconciliation.heldReason())))
                        : commit(directory, reconciliation, cause));
    }

    private Optional<String> 가드로_본다(Set<RelationTuple> desired, Set<RelationTuple> stale, long scanned) {
        GuardDecision decision = guard.evaluate(stale.size(), Math.toIntExact(scanned), "훑은 장부");
        return decision.aborted() ? Optional.of(decision.message()) : Optional.empty();
    }

    /** 스냅샷에는 장부에 실제로 있다고 볼 줄을 담는다(설계 2026-09-29 §3.1 4단계). 그다음 현재상태를 LDAP 대로 바꾼다. */
    private Mono<Mono<SyncOutcome>> commit(DirectorySnapshot directory, TupleReconciler.Reconciliation reconciliation,
                                           AuditCause cause) {
        Instant now = clock.instant();
        TupleSnapshot snapshot = new TupleSnapshot(
                SnapshotIds.generate(now, SyncSource.LDAP), now, SyncSource.LDAP, reconciliation.ledger());

        return snapshots.save(snapshot)
                .then(Mono.defer(() -> state.replaceWith(directory)))
                .map(changes -> Mono.defer(() -> audit.recordRun(cause,
                        new AuditChanges().directory(changes).revoked(reconciliation.result().deleted()).entries(),
                        reconciliation.outcome(snapshot.id()))));
    }
}
```

```java
        return jobs.startLockedThen(SyncSource.LDAP, SyncTrigger.REBUILD, MutationLock.LockPurpose.REBUILD,
                run -> Mono.defer(() -> rebuild(force, run.runId())), onFinished);

    private Mono<Mono<SyncOutcome>> rebuild(boolean force, String runId) {
        return source.fetchAll().flatMap(directory -> {
            TupleMappingResult mapping = TupleMapper.toTuples(directory);
            mapping.warnings().forEach(warning -> log.warn("튜플 변환 경고: {}", warning));
            return alignment.align(directory, mapping.tuples(), force,
                    AuditCause.run(SyncSource.LDAP, AuditKind.REBUILD, runId));
        });
    }
```

```java

     * <p><b>이력(설계 2026-10-10 §4.4).</b> 요청마다 원인(traceId)과 변경 모음 하나를 만들어 커밋 자리들에 넘긴다. 락을 반납하고 다음 요청에 차례를
     * 넘긴 뒤, 응답하기 전에 모은 것을 한 번에 남긴다. 값을 낸 요청만 남긴다 — 오류로 끝난 요청은 커밋을 마치지 못했을 수 있다. 이력 쓰기는
     * 실패해도 요청을 실패시키지 않는다({@link AuditRecorder}).
     */
    private Mono<IncrementalSyncResult> withLock(BiFunction<LockLease, AuditChanges, Mono<IncrementalSyncResult>> work) {
        return Mono.deferContextual(context -> {
            AuditCause 원인 = AuditCause.scimRequest(traceIds.traceIdOf(context));
            AuditChanges 기록 = new AuditChanges();
            Sinks.One<IncrementalSyncResult> 결과 = Sinks.one();
            AtomicBoolean 요청이_떠났다 = new AtomicBoolean();
            // 알리기 전에 본다 — 값을 받은 뒤에 오는 취소는 떠난 것이 아니다.
            잡고_돌린다(lease -> work.apply(lease, 기록), () -> audit.record(원인, 기록.entries()))
                    .contextWrite(context)
                    .subscribe(value -> {
                        if (요청이_떠났다.get() && !value.fullyApplied()) {
                            log.warn("요청이 떠난 뒤 SCIM 쓰기가 부분 반영으로 끝났다 — 실패한 튜플 {}개. IdP 는 이 결과를 받지 못했다",
                                    value.writeResult().failures().size());
                        }
                        결과.tryEmitValue(value);
                    }, error -> {
                        if (요청이_떠났다.get()) {
                            log.warn("요청이 떠난 뒤 SCIM 쓰기가 실패했다 — IdP 는 이 결과를 받지 못했다", error);
                        }
                        결과.tryEmitError(error);
```

```java
package dev.starryeye.organization.core.usecase;

import dev.starryeye.organization.core.audit.AuditCause;
import dev.starryeye.organization.core.audit.AuditChanges;
import dev.starryeye.organization.core.audit.AuditKind;
import dev.starryeye.organization.core.audit.AuditRecorder;
import dev.starryeye.organization.core.model.DirectorySnapshot;
import dev.starryeye.organization.core.model.SyncOutcome;
import dev.starryeye.organization.core.model.SyncRun;
import dev.starryeye.organization.core.model.SyncSource;
import dev.starryeye.organization.core.model.SyncTrigger;
import dev.starryeye.organization.core.model.TupleSnapshot;
import dev.starryeye.organization.core.model.TupleWriteResult;
import dev.starryeye.organization.core.port.DirectoryStateRepository;
import dev.starryeye.organization.core.port.MutationLock;
import dev.starryeye.organization.core.port.RelationTupleScanner;
import dev.starryeye.organization.core.port.RelationTupleWriter;
import dev.starryeye.organization.core.port.TupleSnapshotRepository;
import dev.starryeye.organization.core.tuple.SnapshotIds;
import dev.starryeye.organization.core.tuple.TupleMapper;
import dev.starryeye.organization.core.tuple.TupleMappingResult;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import reactor.core.publisher.Mono;

import java.time.Clock;
import java.time.Instant;
import java.util.Optional;
import java.util.Set;

/**
 * SCIM 인스턴스의 수동 재적재. 관리자가 어긋났다고 판단했을 때 실행한다.
 *
 * <p><b>LDAP 판과 무엇이 다른가.</b> {@link RebuildUseCase} 는 LDAP 을 다시 읽어와 DynamoDB 까지 덮어쓴다. SCIM 은 push 모델이라
 * "전체를 다시 달라"고 말할 상대가 없다 — 그래서 <b>현재상태 자체가 진실</b>이고, {@link ScimRebuildMode#TUPLES} 는 그 상태가
 * 요구하는 튜플에 장부를 맞춘다.
 *
 * <p><b>장부를 버리지 않는다(설계 2026-09-29 §3).</b> 있어야 할 줄을 먼저 다 읽고, 전부 쓴 뒤, 장부를 훑어 없어야 할 줄만 지운다
 * ({@link TupleReconciler}). 읽기가 실패하면 장부에 아무것도 하지 않는다. 장부 번호(storeId)는 바뀌지 않는다.
 *
 * <p><b>보류 목록도 맞춘다(설계 2026-10-03 §4.6).</b> 장부를 맞춘 뒤 보류 목록을 순환이라 버린 연결로 바꾸고, {@code WIPE} 는 조직도와 함께 비운다.
 *
 * <p><b>{@code WIPE} 는 장부를 비운 뒤에만 조직도를 지운다.</b> 청소가 한 줄이라도 실패하면 조직도를 건드리지 않고 FAILED 다 —
 * 조직도가 남아 있어야 다시 실행할 수 있다. 순서를 뒤집으면 조직도가 사라진 채 낡은 권한만 살아남는다.
 *
 * <p><b>요청과 떼어 돈다(설계 2026-09-29 §4, 2026-09-30 §3).</b> {@link #start} 는 {@link SyncJobs#startLockedThen} 으로 작업 락을 잡고 실행 기록을
 * 연 뒤 곧바로 돌아온다. 재적재가 도는 동안 리스를 갱신하고, 리스를 잃으면 멈춰 FAILED 로 남긴다. 순서는 일 → 반납 → 튜플 스냅샷 저장 → 이력 → 기록이다 —
 * 스냅샷 저장과 이력은 락을 반납한 뒤에 해 그동안 SCIM 쓰기를 막지 않는다(설계 2026-10-02 §5, 점검 P8, 설계 2026-10-10 §4.4).
 *
 * <p><b>이력(설계 2026-10-10 §4.2).</b> 회차 id 로 남긴다. {@code TUPLES} 는 지운 줄만 — 쓴 줄은 중복 무시로 써 이미 있던 줄과 가를 수 없다.
 * {@code WIPE} 는 지운 직원·조직과 지운 줄 전부다.
 *
 * <p><b>감사 이력은 지우지 않는다.</b> {@code WIPE} 도 스냅샷, 실행 이력, 변경 이력은 남긴다. 사고 뒤에 "무슨 일이 있었나"를 볼 유일한 기록인데
 * 그것까지 지우면 조사할 수단이 사라진다.
 */
@Slf4j
@RequiredArgsConstructor
public class ScimRebuildUseCase {

    private final DirectoryStateRepository state;
    private final RelationTupleWriter writer;
    private final RelationTupleScanner scanner;
    private final TupleSnapshotRepository snapshots;
    private final SyncJobs jobs;
    private final Clock clock;
    private final AuditRecorder audit;

    /** 이력을 남기지 않는다 — 이력과 무관한 테스트가 쓴다. 운영 결선은 이력을 받는 생성자다. */
    public ScimRebuildUseCase(DirectoryStateRepository state, RelationTupleWriter writer, RelationTupleScanner scanner,
                              TupleSnapshotRepository snapshots, SyncJobs jobs, Clock clock) {
        this(state, writer, scanner, snapshots, jobs, clock, AuditRecorder.NONE);
    }

    /**
     * 작업 락(REBUILD)을 잡고 실행 기록(RUNNING)을 연 뒤 돌려준다. 재적재는 요청과 떼어 돈다 — 결과는 실행 기록으로 본다. 락 잡기·갱신·리스를
     * 잃으면 멈추기·반납과 반납 뒤의 스냅샷 저장·이력은 {@link SyncJobs#startLockedThen} 이 한다. 못 잡으면 {@link LockUnavailableException} 이고
     * 아무것도 시작하지 않는다.
     *
     * <p>{@code WIPE} 의 확인값 검증은 호출자(컨트롤러)의 몫이다. 여기까지 왔다는 것은 이미 확인됐다는 뜻이므로 값 자체는 받지 않는다.
     */
    public Mono<SyncRun> start(ScimRebuildMode mode) {
        log.warn("SCIM 재적재 요청: mode={}", mode);
        return jobs.startLockedThen(SyncSource.SCIM, triggerFor(mode), MutationLock.LockPurpose.REBUILD,
                run -> Mono.defer(() -> rebuild(mode, AuditCause.run(SyncSource.SCIM, AuditKind.REBUILD, run.runId()))),
                run -> {
                });
    }

    private static SyncTrigger triggerFor(ScimRebuildMode mode) {
        return mode == ScimRebuildMode.WIPE ? SyncTrigger.RESET : SyncTrigger.REBUILD;
    }

    /** 락 안에서 할 일을 하고 "반납 뒤 할 일"을 내놓는다 — 튜플 스냅샷 저장과 이력은 락을 반납한 뒤에 한다. */
    private Mono<Mono<SyncOutcome>> rebuild(ScimRebuildMode mode, AuditCause cause) {
        return mode == ScimRebuildMode.WIPE ? wipe(cause) : reloadTuples(cause);
    }

    // ---------- TUPLES ----------

    /** 조직도가 비었는데 장부에 지울 줄이 있으면 지우지 않는다(설계 2026-09-30 §4.3) — 조직도를 잃은 채로 돌면 장부 전체가 지워진다. */
    static final String 빈_조직도 = "조직도가 비어 있다 — 장부를 비우려면 mode=wipe";

    private static final TupleReconciler.DeleteCheck 빈_조직도면_멈춘다 = (desired, stale, scanned) ->
            desired.isEmpty() && !stale.isEmpty() ? Optional.of(빈_조직도) : Optional.empty();

    /** 장부를 맞춘 뒤 보류 목록을 버린 연결로 바꾼다 — 락 안이다. 멈춘 경우(빈 조직도)는 목록을 두고 간다. */
    private Mono<Mono<SyncOutcome>> reloadTuples(AuditCause cause) {
        return state.loadAll().flatMap(directory -> {
            TupleMappingResult mapping = TupleMapper.toTuples(directory);
            mapping.warnings().forEach(warning -> log.warn("튜플 변환 경고: {}", warning));

            return TupleReconciler.reconcile(writer, scanner, mapping.tuples(), 빈_조직도면_멈춘다)
                    .flatMap(reconciliation -> reconciliation.held()
                            ? Mono.just(Mono.just(SyncOutcome.failed(reconciliation.heldReason())))
                            // 재적재는 전체를 정하는 연산이라 보류 목록도 처음부터 다시 정한다(설계 2026-10-03 §4.6)
                            : state.replaceCutEdges(mapping.cutEdges()).thenReturn(commitTuples(reconciliation, cause)));
        });
    }

    /**
     * 스냅샷에는 <b>장부에 실제로 있다고 볼 줄</b>만 담는다(설계 §3.1 4단계). 지우기가 차단기로 멈췄어도 같다 — 스냅샷을 남긴 뒤 FAILED 로 기록한다.
     * <b>락을 반납한 뒤에 돈다</b>(설계 2026-10-02 §5) — SCIM 쓰기 경로는 이 스냅샷을 읽지 않는다. 저장이 실패하면 FAILED 다 — 장부는 이미 맞췄다.
     * 저장한 뒤 지운 줄을 이력에 남긴다(설계 2026-10-10 §4.2).
     */
    private Mono<SyncOutcome> commitTuples(TupleReconciler.Reconciliation reconciliation, AuditCause cause) {
        return Mono.defer(() -> {
                    Instant now = clock.instant();
                    TupleSnapshot snapshot = new TupleSnapshot(
                            SnapshotIds.generate(now, SyncSource.SCIM), now, SyncSource.SCIM, reconciliation.ledger());
                    return snapshots.save(snapshot).thenReturn(reconciliation.outcome(snapshot.id()));
                })
                .onErrorMap(error -> new IllegalStateException("장부는 맞췄다 — 스냅샷 저장 실패: "
                        + (error.getMessage() != null ? error.getMessage() : error.getClass().getSimpleName()), error))
                .flatMap(outcome -> audit.recordRun(cause,
                        new AuditChanges().revoked(reconciliation.result().deleted()).entries(), outcome));
    }

    // ---------- WIPE ----------

    /**
     * 있어야 할 줄이 없다(D = ∅)고 보고 장부를 비운 <b>뒤</b> 조직도를 지운다. 빈 스냅샷으로 교체하면 현재상태의 직원·조직이 전부 지워진다.
     * 이력(지운 직원·조직과 지운 줄)은 락을 반납한 뒤에 남긴다.
     */
    private Mono<Mono<SyncOutcome>> wipe(AuditCause cause) {
        return TupleReconciler.reconcile(writer, scanner, Set.of()).flatMap(reconciliation -> {
            TupleWriteResult result = reconciliation.result();
            if (result.hasFailure()) {
                String 멈춘_이유 = reconciliation.stopReason() == null ? "" : " — 멈춘 이유: " + reconciliation.stopReason();
                return Mono.error(new IllegalStateException(
                        "장부에서 %d줄을 지우지 못해 조직도를 지우지 않았다. 다시 실행하면 남은 줄부터 지운다%s"
                                .formatted(result.failures().size(), 멈춘_이유)));
            }
            // 조직도와 함께 보류 목록도 비운다 — 연결의 멤버 줄이 사라졌으니 보류할 것도 없다
            return state.replaceWith(DirectorySnapshot.empty())
                    .flatMap(changes -> state.replaceCutEdges(Set.of()).thenReturn(changes))
                    .doOnSuccess(changes -> log.warn(
                            "SCIM 조직도를 전부 비웠다. IdP 콘솔에서 전체 재프로비저닝을 실행해야 복구된다"))
                    .map(changes -> Mono.defer(() -> audit.recordRun(cause,
                            new AuditChanges().directory(changes).revoked(result.deleted()).entries(),
                            SyncOutcome.succeeded(result, null))));
        });
    }
}
```

```java
/**
 * 변경 이력 조회(설계 2026-10-10 §5). 대상 하나의 이력을 최신순으로 한 쪽씩 돌려준다. admin-api 라 LDAP·SCIM 배포 둘 다에 들어간다.
 *
 * <ul>
 *   <li>기록이 없는 아이디는 404 가 아니라 빈 목록이다 — 지워진 직원·조직도 30일 동안은 이력이 보인다.</li>
 *   <li>커서는 불투명하다. 이 대상의 커서가 아니거나 망가졌으면 400 이다.</li>
 *   <li>다음 쪽 커서는 이번 쪽이 {@code limit} 줄로 찼을 때 준다 — 마지막 쪽 뒤에 빈 쪽이 하나 올 수 있다.</li>
 * </ul>
 *
 * <p>인증이 없다 — 지금 관리 API 와 같은 노출 수준이다(설계 §10). 이력에는 이전 값(이름·이메일 등)이 담긴다.
 */
@RestController
@RequestMapping("/admin")
@RequiredArgsConstructor
public class AuditHistoryController {

    private static final int DEFAULT_LIMIT = 20;
    private static final int MAX_LIMIT = 100;

    private final AuditLog auditLog;

    @GetMapping("/employees/{employeeId}/history")
    public Mono<Page<AuditHistoryItem>> employeeHistory(@PathVariable String employeeId,
                                                        @RequestParam(required = false) String cursor,
                                                        @RequestParam(defaultValue = "" + DEFAULT_LIMIT) int limit) {
        return history(MemberRef.user(employeeId), cursor, limit);
    }

    @GetMapping("/organizations/{orgCode}/history")
    public Mono<Page<AuditHistoryItem>> organizationHistory(@PathVariable String orgCode,
                                                            @RequestParam(required = false) String cursor,
                                                            @RequestParam(defaultValue = "" + DEFAULT_LIMIT) int limit) {
        return history(MemberRef.group(orgCode), cursor, limit);
    }

    private Mono<Page<AuditHistoryItem>> history(MemberRef subject, String cursor, int limit) {
        if (limit < 1 || limit > MAX_LIMIT) {
            return Mono.error(new ResponseStatusException(HttpStatus.BAD_REQUEST,
                    "limit 은 1 이상 " + MAX_LIMIT + " 이하여야 한다: " + limit));
        }
        return auditLog.history(subject, cursor, limit)
                .map(page -> new Page<>(page.items().stream().map(AuditHistoryItem::of).toList(), page.nextCursor()))
                .onErrorMap(IllegalArgumentException.class,
                        error -> new ResponseStatusException(HttpStatus.BAD_REQUEST, error.getMessage(), error));
    }
}
```

```java
package dev.starryeye.organization.storage;

import software.amazon.awssdk.services.dynamodb.DynamoDbAsyncClient;
import software.amazon.awssdk.services.dynamodb.model.BatchWriteItemRequest;

import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Proxy;
import java.util.concurrent.atomic.AtomicLong;

/**
 * 클라이언트를 감싸 아이템 쓰기(PutItem·UpdateItem) 수와 묶음 쓰기(BatchWriteItem)의 아이템 수를 센다. "바뀌지 않았으면 쓰지 않는다" 를 호출 수로
 * 단정하기 위한 계측이다 — DynamoDB Local 은 GSI 쓰기 용량을 보여 주지 않으므로, 쓰기 요청이 없다는 것까지가 테스트로 증명할 수 있는 선이다
 * (GSI 설계 §9). 직원·조직 META 는 UpdateItem 으로 쓴다(설계 2026-10-09 §3.1). 변경 이력은 묶음 쓰기다(설계 2026-10-10 §4.1).
 */
final class WriteCounter {

    private final AtomicLong writes = new AtomicLong();
    private final AtomicLong batchItems = new AtomicLong();

    DynamoDbAsyncClient wrap(DynamoDbAsyncClient real) {
        return (DynamoDbAsyncClient) Proxy.newProxyInstance(DynamoDbAsyncClient.class.getClassLoader(),
                new Class<?>[]{DynamoDbAsyncClient.class},
                (proxy, method, args) -> {
                    if (method.getName().equals("putItem") || method.getName().equals("updateItem")) {
                        writes.incrementAndGet();
                    }
                    if (method.getName().equals("batchWriteItem") && args[0] instanceof BatchWriteItemRequest request) {
                        request.requestItems().values().forEach(items -> batchItems.addAndGet(items.size()));
                    }
                    try {
                        return method.invoke(real, args);
                    } catch (InvocationTargetException e) {
                        throw e.getCause();
                    }
                });
    }

    long writes() {
        return writes.get();
    }

    /** 묶음 쓰기로 보낸 아이템 수. 처리 못 해 다시 보낸 것도 다시 센다. */
    long batchItems() {
        return batchItems.get();
    }

    void reset() {
        writes.set(0);
        batchItems.set(0);
    }
}
```

````markdown
### 변경 이력(감사 로그)

직원·조직마다 "언제, 무엇 때문에, 무엇이 바뀌었나" 를 남긴다(설계 `docs/superpowers/specs/2026-10-10-audit-log-design.md`).

```json
{"items":[{"at":"2026-10-10T03:00:00.123Z",
  "cause":{"source":"SCIM","kind":"SCIM_REQUEST","id":"4bf92f3577b34da6a3ce929d0e0e4736"},
  "created":false,"deleted":false,
  "attributes":[{"name":"displayName","before":"김철수","after":"김철수2"}],
  "joined":[],"left":[],"granted":[],"revoked":[]}],
 "nextCursor":null}
```

- **한 줄은 대상 하나 × 사건 하나다.** 사건은 동기화·재적재 회차 하나, 또는 SCIM 요청 하나다.
- **원인(`cause`).**
  - `source` 는 `LDAP`·`SCIM` 이다.
  - `kind` 는 `SYNC`·`REBUILD`·`LEDGER_ALIGNMENT`(기록 전에 멈춘 회차 뒤의 동기화)·`SCIM_REQUEST` 다.
  - `id` 는 회차면 `/admin/sync/runs` 의 `runId`, SCIM 요청이면 로그의 traceId 다.
- **조직도 변경.**
  - `created`·`deleted`.
  - 바뀐 속성(`attributes`): 직원은 `externalId`·`userName`·`displayName`·`email`·`active`·`name.*`, 조직은 `externalId`·`displayName`.
  - 들어간·나간 조직(`joined`·`left`).
  - 조직 줄만 멤버 들어옴·나감(`membersAdded`·`membersRemoved` — `count` 와 `items`).
- **권한 변경.** 이 대상이 user 쪽인 튜플 중 실제로 쓴 것(`granted`)과 지운 것(`revoked`)이다.
- **남기지 않는 것.**
  - 재적재·장부 맞추기가 "쓴" 튜플. 중복 무시로 써서 이미 있던 줄과 가를 수 없다. 지운 줄은 남긴다.
  - 아카이빙. 상태를 바꾸지 않는다.
- **보관.**
  - 보관 기간은 `dynamodb.audit-retention-days`(기본 30일)다. 늘리려면 `dynamodb.syncrun-retention-days` 와 함께 늘린다.
  - 테이블 TTL 이 지우므로, 기한이 막 지난 줄이 며칠 보일 수 있다.
  - 지운 직원·조직의 이력도 그동안 보인다. `wipe` 도 이력을 지우지 않는다.
  - 기록이 없는 아이디는 404 가 아니라 빈 목록이다.
- **빠질 수 있다.**
  - 이력은 커밋한 뒤, 락을 반납한 뒤에 쓴다.
  - 쓰기가 끝내 실패해도 동기화·SCIM 요청은 실패하지 않는다. 대신 셋이 남는다.
    - ERROR 로그.
    - 지표 `audit.write.failures`.
    - 회차 메시지 앞의 `감사 기록 N건 실패`.
- **SCIM 의 확인 없는 지우기.** 조직 멤버 빼기와 조직 삭제는 줄을 확인 없이 지운다. 그래서 비활성 직원처럼 원래 없던 줄도 `revoked` 에 나올 수 있다.
- **큰 조직.** 10만 명 조직이 한 회차에 통째로 바뀐 줄(초기 적재·`wipe`)은 응답 하나가 수 MB 다.
- **다음 쪽.** 쪽이 `limit` 줄로 차면 `nextCursor` 를 준다. 그래서 마지막 쪽 뒤에 빈 쪽이 하나 올 수 있다.
- **인증이 없다.** 이력에는 이전 값(이름·이메일 등)이 담긴다. 다른 관리 API 처럼 앞단에서 보호해야 한다.
````
