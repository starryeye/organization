# 인증 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버에 인증을 넣는다.
- 인가 서버 `app-auth` 가 client credentials 로 JWT 를 발급한다.
- 두 앱은 범위로 SCIM·관리 API·actuator 를 지킨다.
- 감사·회차에 행위자를 남기고, 정확 조회 둘을 더하며, OpenFGA 에 키를 싣는다.

**Architecture:**
- `app-auth`(새, 서블릿)는 Spring Authorization Server 를 Boot 속성으로 띄운다. 두 앱은 새 모듈 `web-security`(WebFlux `SecurityWebFilterChain`)를 쓰는 리소스 서버다.
- 행위자는 웹 필터가 Reactor Context 에 싣고 core 가 그 Context 에서 읽는다(core 는 Spring 을 모른다).
- 시험은 `web-security` testFixtures 의 고정 키로 서명한 토큰을 `WebTestClient` 기본 헤더로 싣는다. 진짜 인가 서버 시험은 하나 따로 둔다.

**Tech Stack:**
- Java 17, Spring Boot 3.5.16(Spring Security 6.5, Spring Authorization Server 1.5), WebFlux/Reactor, Spring MVC(app-auth 만)
- Nimbus JOSE(JWT), AWS SDK v2 DynamoDB, OpenFGA Java SDK 0.9.11
- JUnit 5·AssertJ·Testcontainers, spring-security-test

**Spec:** `docs/superpowers/specs/2026-10-28-auth-design.md` — 설계가 권위다. 이 계획과 부딪히면 설계를 따른다. 코드 사실은 `.superpowers/auth/research-code.md`(git 무시)에 있다.

## Global Constraints

- 코드 관례: 기존 코드처럼 한국어 메서드·변수 이름. 시험 메서드는 한국어 이름 + `@DisplayName` 한국어 문장, 본문은 `// given / when / then`, 단언은 AssertJ.
- Gradle: 한 번에 하나만. 구현 서브에이전트는 자기 과제의 모듈 시험만 돌린다. 전체 `test`·`scaleTest` 는 컨트롤러가 머지 전에 돌린다.
- git: `git stash` 금지. 커밋 메시지는 한국어 `fix:`/`feat:`/`docs:`/`test:` 한 문장 + `(인증)`, 끝줄 `Co-Authored-By: <모델 이름> <noreply@anthropic.com>`. 바꾼 파일만 스테이징.
- OpenFGA Read(`RelationTupleScanner`)는 재적재와 기준선을 믿을 수 없는 LDAP 회차에서만. 판단·쓰기는 Check·BatchCheck. 규모 10만 명: 요청마다 전원을 읽지 않는다. 배포 하나에 커넥터 하나. 운영 배포 전이라 옛 아이템을 이관하지 않는다(없는 속성은 빈 값으로 읽는다).
- 범위 이름(정확히): `scim`, `admin.read`, `admin.sync`, `admin.destructive`, `directory.lookup`, `actuator`. 권한 이름은 `SCOPE_<범위>`.
- 행위자 값: 토큰 요청 `client:<sub>`, 예약 LDAP 동기화 `system:scheduler`, SCIM 아카이빙(그 회차와 남은 회수 지우기) `system:archive`, 찾지 못함 `system:unknown`(WARN).
- 설계가 정한 문구(그대로):
  - 401 detail `인증이 필요하다`, 403 detail `이 요청에 필요한 범위가 없다`
  - 위험 요청 403: `<무엇>은 admin.destructive 범위가 필요하다` — `<무엇>` 은 `force=true` 또는 `mode=wipe`
  - 직원 조회: 404 `일치하는 직원이 없다`, 409 `<N>명이 일치한다 — externalId 로 찾는다`
  - 조직 조회: 404 `일치하는 조직이 없다`, 409 `<N>개가 일치한다`
  - OpenFGA: `openfga.require-api-token 인데 openfga.api-token 이 비었거나 풀리지 않은 자리표시자다 — 환경 변수 OPENFGA_API_TOKEN 을 준다`
- `WWW-Authenticate`(RFC 6750): 토큰 없음 `Bearer`, 토큰이 잘못됨·만료 `Bearer error="invalid_token"`, 범위 부족 `Bearer error="insufficient_scope"`.
- 숫자: 토큰 수명 기본 10분, IdP 용 60분 권장, 클라이언트 수명 상한 365일(넘으면 기동 멈춤). app-auth 로컬 포트 9000, 발급자 로컬 `http://localhost:9000`.
- 환경 변수: `AUTH_SIGNING_KEY`(app-auth 개인 키 PEM), `OPENFGA_API_TOKEN`.
- 시험 상수: 시험 발급자 `https://auth.test`, 시험 OpenFGA 키 `test-openfga-key`, 시험 클라이언트 `sub` `test-client`.

## Review Focus

- **IdP 가 토큰 요청에 `scope` 를 보내지 않는다.** 등록된 범위를 모두 받아 SCIM 이 통과해야 한다. 아니면 모든 SCIM 호출이 403 이다(Task 4).
- **`force=yes`·`force=1` 처럼 스프링이 true 로 바꾸는 값을 `admin.sync` 만으로 보낸다.** 403 이고 회차가 생기지 않는다(Task 7).
- **올바른 범위를 가졌지만 다른 키로 서명했거나 발급자가 다른 토큰.** 401 이다(Task 5).
- **IdP 가 SCIM 쓰기 도중 연결을 끊는다.** 쓰기는 계속 돌고, 감사 줄의 행위자는 `client:<sub>` 그대로 남는다(Task 2).
- **인가 서버가 꺼져 있거나 닿지 않는다.** 리소스 서버는 그래도 뜨고 프로브는 200 이다. 토큰이 있는 요청은 500 이 아니라 401 이다(Task 6).
