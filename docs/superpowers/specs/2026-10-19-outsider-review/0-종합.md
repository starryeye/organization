심각도는 프로젝트 맥락(10만 명, 커넥터 하나, 배포 전)에서 검증자가 매긴 값이다.

## 4. 이미 결정·수용한 것 (리뷰어가 다시 짚었지만 문서에 근거가 있음)

- 펜싱이 없다 (cluster-jobs §11, big-change-lock §10).
- 영구 거절 줄 하나가 뒤 단계 부여를 막는다. fail-closed 를 골랐다 (README:889-890, ldap-read §5).
- 계정 상태 속성이 없으면 활성이다 (disabled-account §2·§6). `msDS-UserAccountDisabled`·`shadowExpire` 지원 여부는 별개 문제다.
- 비정규화가 단사가 아니고, 먼저 읽은 쪽이 이기며, AD 기본 그룹은 RID 만 본다 (08-14 §4.3, ldap-read §3.2, README:506-508).
- 비활성 중에는 멤버십을 유지한다 (disabled-account, full-audit:1329).
- SCIM 의 결과 모르는 쓰기가 남긴 고아 튜플, 실패한 `POST /Groups` 의 고아 튜플 (09-01 §5.4, ④-1 §11). 재적재만 지운다.
- SCIM 목록 책갈피를 호출자끼리 공유한다 (scim-list-filter §4.4).
- 전역 락의 처리량 상한 ("실제 요구가 확인될 때").
- GSI 파티션 키가 상수다 (GSI1 쏠림 슬라이드).
- 감사: 30일, 최선 노력, 같은 테이블 (10-10 §2·§3.5·§4.5). 행위자 칸과 변경 불가 저장소는 논의된 적이 없다.

## 5. 인증 슬라이드가 맡을 것

리뷰 넷의 Critical 은 전부 여기에 속한다.

- SCIM 인증: IdP 별 토큰 또는 OAuth2, `authenticationSchemes`.
- 관리 API·actuator 분리와 인증:
  - wipe 의 확인값이 공개된 테이블명뿐이다.
  - `force` 를 누구나 부를 수 있다.
  - PII 조회가 열려 있다.
  - 익명 비용 증폭이 가능하다: COUNT, startIndex 건너뛰기, 직원 상세 하나에 Check 200번.
- OpenFGA 자격 증명이 없어 Write 권한을 이 서버로만 좁힐 수 없다.
- 감사 행위자: 누가 wipe·force 를 걸었는지 남긴다.
- 로그인 → employeeId 매핑용 인증된 정확 일치 API (N10 과 함께).

## 6. 소유자가 정할 것

1. **Read 원칙:** 탐지 전용 정기 장부 대조(락 없음, 쓰기 없음)를 허용할지. N1·N6·펜싱 틈이 남기는 잉여를 찾는 유일한 길이다.
2. **N1 고치는 범위:** 셋 가운데 고른다.
   - 차단기 FAILED 만 표시를 남긴다. 원칙 안이다.
   - PARTIAL 까지 남긴다. Read 조건이 넓어진다.
   - 불확실한 묶음을 기록한다. Read 가 없다.
3. **N2:** SCIM 비활성화의 요청값(`false`)을 바로 저장할지. 근거가 낡았다. 서버 쪽 재시도(아웃박스)까지 둘지도 정한다. 09-01 §1.4 는 아웃박스를 버렸다.
4. **N3 가드:** 원인별(비활성 vs 사라짐) 비율, 절대 수 상한, 부여 가드.
5. **회수 SLO:** 이것으로 LDAP 기본 주기, 읽기 재시도 창, 신선도 경보의 기준이 정해진다.
6. **N5:** SCIM 배포의 조직 계층을 어디서 받을지. 선택지는 enterprise 속성과 조직 마스터, HRIS, 관리 API 다. 최소한 README 에 한계를 적는다.
7. **`active` 기본값의 방향.** 지금 규칙을 둘지 뒤집을지.
