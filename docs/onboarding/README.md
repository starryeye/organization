# 읽는 법

> 기준 커밋: 5675b3c (ops-readiness, main 에 머지됨). 코드가 바뀌면 이 문서도 함께 고친다.
> 읽기 전에: 없다 — 이 묶음의 입구다.

이 디렉터리(`docs/onboarding/`)는 조직도 동기화 서버를 **처음 보는 개발자·운영자**를 위한 문서 묶음이다. Java·Spring 은 알지만 이 시스템, OpenFGA, SCIM, LDAP 의 세부는 모른다고 가정한다. 이 묶음 하나로 시스템이 무엇을 하는지, 모든 동작이 실제로 어떻게 일어나는지 끝까지 따라갈 수 있게 썼다.

## 이 묶음은 무엇이고, 무엇이 아닌가

| 이 묶음은 | 이 묶음이 아닌 것 |
|---|---|
| **지금의 동작**을 주제별로 담는다. "언제 바뀌었나" 는 쓰지 않는다 | 슬라이드별 작업 기록이 아니다. 그것은 `docs/superpowers/specs/`(설계·점검·리뷰)와 `docs/superpowers/plans/`(구현 계획)에 시간순으로 쌓여 있다 |
| 코드를 직접 읽고 썼다. 코드와 다르면 코드가 맞다 | [루트 README.md](../../README.md)(저장소 루트의 것)를 대신하지 않는다. 루트 README.md 는 운영자가 설정·경보를 찾는 참조로 계속 쓴다. 이 디렉터리의 README.md 는 이 문서, "읽는 법" 이다 |
| 동작을 바꾸는 슬라이드마다 **함께 고쳐** 늘 최신으로 둔다 | 한 번 쓰고 버리는 문서가 아니다. 고치지 않으면 몇 슬라이드 만에 또 하나의 낡은 기록이 된다 |
| 확인하지 못한 것은 "확인하지 못했다" 고 적는다 | 실제 AD·실제 AWS·실제 IdP·10만 명 규모에서 잰 결과가 아니다([13 한계와 알려진 문제](13-한계와-알려진-문제.md)) |

## 5분 요약

**무엇을 하나.** 회사 앱들은 "이 사람이 이 조직(또는 그 하위 조직)에 속하는가" 를 묻는다. 이 서버는 디렉터리의 조직도를 OpenFGA [장부](02-용어집.md#장부)(store)에 [튜플](02-용어집.md#튜플)(관계 한 줄)로 옮겨 둔다. 앱은 OpenFGA 에 `Check(user:<employeeId>, member, group:<orgCode>)` 하나만 묻는다. 상위 조직으로 올라가는 계산([롤업](02-용어집.md#롤업))은 OpenFGA 의 [인가 모델](02-용어집.md#인가-모델)이 한다. 이 서버가 쓰는 튜플은 둘뿐이다 — `direct_member`(직원 → 조직)와 `child`(하위 조직 → 상위 조직). LDAP·SCIM·OpenFGA 가 처음이면 [01 개요 — 0절](01-개요.md#0-처음이라면-ldapscimopenfga-한-쪽-요약)부터 읽는다.

**두 앱, 배포 하나에 하나.** 원천에 따라 둘 중 하나만 띄운다.

- **app-ldap**(pull) — 매시 정각 LDAP/AD 전체를 읽는다. 직전 [튜플 스냅샷](02-용어집.md#튜플-스냅샷)을 [기준선](02-용어집.md#기준선)("장부에 지금 이것이 있다" 고 보는 출발점)으로 삼아 차이만 쓴다([비교 경로](02-용어집.md#비교-경로)). 기준선을 믿을 수 없으면(첫 회차, 지난 회차가 기록 전에 멈춤) 장부를 훑어 맞춘다([장부 맞추기](02-용어집.md#장부-맞추기)). 지울 것이 30% 를 넘으면 [삭제 가드](02-용어집.md#삭제-가드)가 멈춘다.
- **app-scim**(push) — IdP(Okta, Entra)가 보낸 요청 하나하나를 처리한다([SCIM 쓰기](02-용어집.md#scim-쓰기)). 영향 범위만 담은 [최소 그림](02-용어집.md#최소-그림)을 만들고, 장부에 `Check` 로 물어 지금 있다고 확인한 줄([Check 기준선](02-용어집.md#check-기준선))과의 차이를 쓴다. 다시 보내면 나을 실패는 503 과 `Retry-After` 로 알린다.

**데이터는 두 곳.** OpenFGA 장부(튜플뿐, 권한을 묻는 앱이 읽는 것)와 DynamoDB 테이블 하나([현재상태](02-용어집.md#현재상태) — 이름·이메일·소속, 튜플 스냅샷, [실행 기록](02-용어집.md#실행-기록), [감사 이력](02-용어집.md#감사-이력), 락과 운영용 줄). 튜플에는 [불변 id](02-용어집.md#불변-id)만 있다.

**스스로 맞춘다.** 재시도 큐가 없다. 실제로 반영됐다고 확실한 줄만 다음 기준선에 넣고, 결과를 모르는 줄은 [불확실 줄](02-용어집.md#불확실-줄)로 따로 적어 다음 회차가 다시 잡는다. 관리자는 [재적재](02-용어집.md#재적재)로 장부 전체를 맞출 수 있고, app-scim 은 하루 한 번 [아카이빙](02-용어집.md#아카이빙)으로 [드리프트](02-용어집.md#드리프트)를 세고 [남은 회수](02-용어집.md#남은-회수)를 지운다.

**한 번에 하나.** 여러 대를 띄워도 일은 DynamoDB 로 만든 [변경 락](02-용어집.md#변경-락) 하나로 줄 선다. 완벽한 상호 배제는 아니다 — OpenFGA 에 [펜싱](02-용어집.md#펜싱)이 없다.

**아직 없는 것.** **인증이 없다.** 관리 API(`/admin/**`), SCIM(`/scim/v2/**`), actuator 가 모두 열려 있다. 운영에 넣기 전에 앞단에서 막아야 한다. 아직 운영 배포 전이라 데이터는 초기화해도 되고 이관 코드는 만들지 않는다.

더 긴 개요는 [01 개요](01-개요.md)다.

## 약속

**용어집이 먼저다.** 이 묶음은 [02 용어집](02-용어집.md)의 말만 쓴다. 같은 것을 다른 이름으로 부르지 않는다. 각 항목의 `###` 제목이 정식 이름이고 링크의 앵커다(예: `[장부](02-용어집.md#장부)`). 코드 주석이나 루트 README.md 가 다른 말을 쓰면 용어집의 "다른 이름" 과 쓰지 않는 말에 적었다. "이 묶음" 은 이 문서 묶음을 가리킨다.

**코드가 기준이다.** 숫자·이름(기본값, 설정 키, 지표 이름, 오류 문구, HTTP 상태, 키 형식)은 코드와 설정에서 그대로 옮겼다. 루트 README.md·설계 문서와 코드가 다르면 코드대로 쓰고 다른 곳을 밝혔다. 코드의 동작이 놀라운 곳은 [13 — 7절](13-한계와-알려진-문제.md#7-코드를-읽어-확인한-문제)에 모았다. 이 묶음과 코드가 다르면 코드가 맞다 — 문서를 고친다.

**코드 위치는 클래스·메서드 이름으로 쓴다.** 예: `FullSyncUseCase.synchronize`, `LedgerAlignment` 의 `가드로_본다`. 줄 번호는 쓰지 않는다 — 금방 낡는다. 클래스가 처음 나올 때 모듈을 한 번 적는다(예: `DeletionGuard`(core `guard`), `DynamoDbMutationLock`(storage-dynamodb)). 메서드·상수 이름이 한국어인 곳이 많다([03 — 한국어 식별자](03-아키텍처.md#8-한국어-식별자)).

**인용은 그대로 둔다.** 로그·오류 문구·메시지 상수는 코드의 글자 그대로 따옴표나 코드 표기로 옮긴다. 그 안에는 용어집과 다른 말(예: "어긋남", "작업 락")이 남아 있을 수 있다.

**확인하지 못한 것은 그렇다고 쓴다.** 실행해 보지 않고 코드에서 따진 것은 "코드에서 도출했다", 재지 않은 수치는 "추정" 이라고 밝혔다.

**"더 깊이" 만 설계 문서를 가리킨다.** 본문은 설계 문서 없이 이해되게 썼다. 배경이 궁금하면 절 끝 "더 깊이" 의 링크를 따라간다.

## 최신으로 지키는 법

> **동작을 바꾸는 슬라이드는 이 묶음의 바뀐 절을 함께 고치고, 고친 문서 머리의 "기준 커밋" 줄을 올린다.**

- 문서마다 머리에 `기준 커밋: <해시> (…)` 가 있다. 그 문서를 코드와 맞대 본 커밋이다. 슬라이드 브랜치에서 고치면 그 브랜치의 마지막 코드 커밋과 브랜치 이름을 적는다(예 `5675b3c (ops-readiness, main 에 머지됨)`) — 머지는 커밋을 그대로 main 에 들인다. 내용을 고치거나 다시 확인했으면 올리고, 건드리지 않은 문서는 그대로 둔다. 코드나 빌드가 이 줄을 검사하지 않는다 — 사람이 지킨다.
- 구현 계획의 마지막 과제에 "온보딩 문서 갱신(바뀐 절만)" 을 넣고, 최종 리뷰에서 이 묶음과 코드가 맞는지도 본다([14 — 온보딩 문서를 함께 고친다](14-개발-가이드.md#66-온보딩-문서를-함께-고친다)).
- 새 말이 필요하면 [02 용어집](02-용어집.md)에 `###` 항목을 먼저 더하고 목차에 넣는다. 옛 말을 버리면 "쓰지 않는 말" 표에 옮긴다.
- 제목을 바꾸면 앵커가 바뀐다. 다른 문서의 링크를 함께 고친다. 앵커는 GitHub 규칙을 따른다 — 소문자로 바꾸고, 글자·숫자·`-`·`_` 와 한글만 남기고(`.`, `·`, `—`, 괄호, 백틱은 빠진다), 공백은 `-` 가 된다. 예: `### 3.1 정기 장부 대조가 없다 — 원칙이다` → `#31-정기-장부-대조가-없다--원칙이다`.
- [13 한계와 알려진 문제](13-한계와-알려진-문제.md)의 항목을 고치는 슬라이드는 그 항목의 상태를 바꾸거나 지운다.
- 루트 README.md 와 이 묶음은 둘 다 코드와 맞아야 한다. 슬라이드가 루트 README.md 를 고치면 이 묶음도 본다.
